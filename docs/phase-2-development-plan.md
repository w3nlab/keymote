# Keymote 二期开发计划

## 目标

二期让用户能够为任意 macOS 应用创建按键 Profile、让一个遥控器动作触发用户定义的快捷键，并建立安全、可验证的应用更新机制。现有预定义 Profile、默认 Profile 继承关系和已保存的映射必须保持兼容。

## 范围与阶段

### 1. 自定义 Profile

**交付内容**

- 在 Profile 列表中提供“新增 Profile”“编辑”“删除”操作。
- 通过 `NSOpenPanel` 选择 `.app`，自动读取应用名称、图标和 bundle identifier；允许用户修改显示名称。
- 自定义 Profile 绑定到 bundle identifier，在该应用成为前台应用时自动生效。
- 自定义 Profile 与预定义 Profile 使用同一套单击、双击、长按映射编辑器，并可将任一动作设为“默认”来继承 Default Profile。
- 当选择的应用没有稳定 bundle identifier 时，提示用户该 Profile 无法可靠自动匹配，不保存为自动 Profile。

**数据模型与迁移**

- 将当前固定的 `AppProfile` 映射扩展为“内置 Profile + 用户 Profile ID”。
- 用户 Profile 保存 UUID、显示名、bundle identifier、可选图标书签/缓存和映射。
- 将当前配置迁移为内置 Profile；不改写用户已有按键动作。
- 删除 Profile 仅删除该 Profile 与映射，Default Profile 不可删除。

**验收**

- 用户可为任意已安装、有 bundle identifier 的应用创建、编辑、删除 Profile。
- 切换到该应用时映射自动切换；删除后回退到 Default Profile。

### 2. 用户自定义快捷键 Action 与冲突管理

**交付内容**

- 新增预定义 Action：“发送自定义快捷键”。
- Action 配置页支持录制组合键（修饰键 + 主键），并显示标准化名称，例如 `⌘⇧P`。
- 执行时通过现有辅助功能/CGEvent 通道向当前前台应用发送该快捷键。
- 支持将一个已保存的快捷键 Action 复用到多个按钮和 Profile。

**冲突规则**

- 同一 Profile 内，同一“按钮 + 手势”只能有一个 Action（沿用现有结构）。
- 发现多个“按钮 + 手势”映射到同一快捷键时显示警告，但默认允许：这可用于为同一个功能提供多个遥控器入口。
- Default Profile 与子 Profile 的“默认”继承不视为冲突；子 Profile 显式覆盖时在 UI 中标明来源。
- 如果快捷键录制为空、只有修饰键、或不能生成合法 CGKeyCode，则禁止保存并给出原因。
- 在系统快捷键或应用自身快捷键未知、且 macOS 没有稳定公开查询接口时，标为“潜在冲突”，而不做不可靠的自动拦截；用户可继续保存。

**验收**

- 可创建、编辑、删除并分配自定义快捷键 Action。
- 无效组合键不能保存；重复映射和可能的系统冲突均能被清晰提示。
- 无障碍权限缺失时不注入快捷键，并给出可操作的权限提示。

### 3. 版本更新管理

**交付内容**

- 采用 Sparkle（macOS 常用更新框架）实现检查、下载、签名验证和安装更新。
- 在设置中提供“自动检查更新”开关、“检查更新”按钮、当前版本和更新状态。
- 支持启动后延迟检查、每日节流、失败重试与离线错误提示；不阻塞遥控器服务。
- 发布产物生成 appcast feed，使用 EdDSA 签名；更新包与签名在 CI/发布脚本中生成。
- 增加发行说明页，并区分稳定版与测试版更新通道（测试版仅在后续启用）。

**安全与发布流程**

1. 使用 Developer ID 签名、Hardened Runtime、Notarization 和 staple 生成发行版。
2. 为 Sparkle 生成独立 EdDSA 密钥；私钥只保存在受控发布环境，公钥嵌入应用。
3. CI 构建、签名、notarize、打包、生成签名 appcast 条目，再发布到 HTTPS 静态源。
4. 先在测试通道验证升级与回滚预案，再提升至稳定通道。

**验收**

- 应用可发现、下载并验证一个签名有效的较新版本。
- 无效签名、降级版本、网络失败不会安装或损坏当前应用。
- 用户可以关闭自动检查，并可手动检查更新。

## 建议实施顺序

1. 先重构 Profile 标识与配置迁移，完成自定义 Profile。
2. 在稳定映射模型上增加可序列化的快捷键 Action 和冲突检查。
3. 最后接入 Sparkle 与发布自动化；这部分需要 Developer ID、Apple notarization 凭据及一个 HTTPS 更新源。

## 测试策略

- Core 单元测试：配置迁移、Profile 解析/回退、继承、快捷键合法性、冲突诊断。
- UI 测试：创建/编辑/删除 Profile，快捷键录制与提示。
- 集成测试：在测试应用中验证 CGEvent 快捷键发送。
- 更新测试：使用本地/测试 appcast 验证有效更新、签名失败和网络中断路径。

## 非目标

- 不尝试通过私有 API 枚举每个第三方应用的全部快捷键。
- 不把用户的云端模型密钥、语音录音或 Profile 配置上传到更新服务。
